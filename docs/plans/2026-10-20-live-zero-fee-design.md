# Live MEXC Futures і вибір контрактів із нульовою комісією — робочий дизайн

Дата: 2026-10-20. Статус: проєкт рішення; жоден Live gate не прийнятий.

## Мета й поточна межа

Користувач попросив довести систему до реальних ордерів і коштів та вибирати ф'ючерси із зони нульових комісій MEXC. Чинна реалізація має лише BTC_USDT Paper worker/bots, public MEXC adapter і локальну автентифікацію. `APP_MODE` приймає тільки `paper`, а `LIVE_TRADING_ENABLED=true` відхиляється при старті. Наявні Paper fees — оцінка з публічних правил, не тариф акаунта. Не вважати цей запит дозволом на будь-який конкретний ордер без символу, обсягу та лімітів.

## Обраний шлях

1. **Read-only каталог.** Показувати публічний список MEXC Futures із server time, UTC часом спостереження, raw rules hash, станом торгівлі, прапорцями zero-fee та public maker/taker rates. Це лише публічна позначка промоакції. [Чинні умови 0-Fee Fest](https://www.mexc.com/zero-fee), прочитані 2026-10-20, прямо виключають API users із 0% акції. Отже каталог не є списком безкомісійних контрактів для бота. Невідоме/неповне поле не трактувати як нуль. Зміна правил скидає придатність.
2. **Акаунтна перевірка.** Користувач обрав обов'язкове 0% **maker саме для API-угод його акаунта**; 0% taker не потрібні. Після окремого налаштування ключа з мінімальними правами читати приватні фактичні maker/taker rates для вибраного контракту. Умови 0-Fee Fest виключають API users, тому до письмового підтвердження MEXC, актуальної акаунтної ставки maker=0 та незалежно перевіреної прив'язки підтвердження до акаунта/символу Live не допускається. Такого підтвердження зараз немає. Перед кожним новим Live-входом повторно перевіряти тариф; при зміні/timeout/суперечності — `WAIT`. Ненульову taker ставку, funding, спред і прослизання показувати окремо. Сам 0% maker не гарантує 0 fee за fill; post-only семантику API ще треба офіційно перевірити.
3. **Один вибраний контракт на перший пілот.** Розширити market ingest, bot config та Risk Engine до явного символу без перенесення Paper балансу або позиції. Для кожного символу потрібні свіжі WS/REST дані, актуальні contract rules і окремий стан якості. Кандидати без підтвердженого market/risk contract не можуть перейти до Live.
4. **Окремий Live контур.** Власні рахунок, ордери, виконання, позиції й ledger. Підписаний приватний адаптер не доступний AI/UI. Записати intent і `ALLOW` risk verdict до мережевого запиту. Невідома відповідь або збій між send і commit ставить `BROKER_UNKNOWN`, блокує нові входи й запускає reconciliation за фактичними order/deal/position/account даними; виконання не домислювати. Kill switch блокує збільшення ризику; reduce-only close перевіряти окремо.
5. **Операційне приймання й пілот.** Закрити Stage 8: розібрати повторні transport/quality alerts та історичний outbox, перевірити доставку в тестовий канал, довший Paper soak, backup/restore і процесні faults. Перевірити чинні MEXC API/scopes, регіональні умови, ключ без withdrawal, IP binding, time sync, rate limits, dry-run, незалежний review. Серверний Live gate лишається вимкненим до всіх доказів та окремого запуску з визначеними символом і лімітами.

## Критерії приймання

- Каталог не називає контракт «0% для API-бота» через public rate/прапорець; умови виключення API users, account rate й UTC спостереження видно окремо. Порожня, застаріла, суперечлива чи недоступна відповідь дає неактивний вибір.
- Тести з контрольованими відповідями перевіряють sign/clock/permission failures, неповний та частковий fill, дубль після restart, timeout після send, cancel/close, stale market/rules/fees, kill і режимну ізоляцію. Жоден автоматичний тест не використовує реальний ключ або кошти.
- Перед першим реальним ордером існує документований незалежний review і фактичний runbook для `UNKNOWN`, WS/API/DB/Redis outage, розбіжності балансу та аварійної зупинки. Окрема проба з реальними коштами потребує явних параметрів і перевірки всіх gates безпосередньо перед нею.

## Відкриті рішення

- Числові ліміти першого Live пілота та місце постійного хостингу: користувач визначив максимум **повного номіналу позиції** в USDT або % equity, TP/SL у % і плече як обов'язкові налаштування, але значень ще немає. Потрібен також окремий денний ліміт збитку та обмеження кількості позицій.
- Поточний документований список zero-fee контрактів, персональна ставка та доступність приватних endpoint для конкретного акаунта; без ключа це не підтверджено.

Джерела й дату повторної офіційної перевірки внести до `docs/MEXC_API.md`; фактичні результати кожного етапу — до `docs/IMPLEMENTATION.md`. Цей дизайн не є доказом готовності Live.
